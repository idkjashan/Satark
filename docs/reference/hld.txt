# Satark — Scam Check & Learn for Bharat
High-Level Design (HLD) for Track A (Digital Fraud & Scam Resilience) and Track C (Investor Education for Bharat)
“Satark” (सतर्क) means alert, watchful. It is a working name; changing it later does not affect the design.
Track A — check before payingShare a suspicious message, screenshot, link or UPI (Unified Payments Interface) ID and get an evidence-backed verdict and the next safe step.
Track C — learn by experiencingTwo-minute, regional-language simulations of the exact trap, with ₹0 at risk.
Guardrails built inNo tips, no login, no user data on our servers, and uncertainty stated openly.

## 0. TL;DR: the decision in four lines
 Verdict
- Build Satark: a voice-first, regional-language PWA (progressive web app: a website that installs and works like an app). An investor shares a suspicious WhatsApp message, screenshot, link, UPI ID or “tip”. In under ~10 seconds they get an evidence-backed risk verdict, the next safe action, and a 2-minute simulation of that trap. No login, and nothing about the user is stored on our servers.
- The core is a bounded check pipeline, not an open-ended agent. Deterministic verifiers produce the evidence: the SEBI registry snapshot, SEBI’s validated-UPI-handle rules, caution lists from NSE and BSE (India’s two main stock exchanges) and the RBI (Reserve Bank of India), and domain-age and web-address (URL) reputation checks. A rules-based scorer turns that evidence into the verdict. The LLM (large language model) does two things only: it reads messy input into structured entities, and it explains the verdict in the user’s language. A small agent loop (at most 3 tool rounds) handles follow-up questions.
- Harness approach: keep skills as Markdown files, tool calling and multi-round reasoning, but do not fork Goose or a chat UI (user interface). Goose is a single-owner coding agent: one shared secret for all clients, a shell tool on by default, and a ~27 K-token prompt prefix (§10.1). Write our own ~300-line pipeline and use PydanticAI only as the model layer. It gives one interface for Gemini and Claude, typed JSON (structured data) outputs, and a tool loop with hard usage limits. RAG (retrieval-augmented generation) is not needed at this size of knowledge base. MCP (Model Context Protocol) is worth adding only to let other apps reuse our verifier, not inside the request path.
- Main risk: time. The sprint ends on 4 Oct 2026. Build the “Must” list in §3.2 first: one golden journey in Hindi and English, plus one simulator. Only then add anything else.
 Why this shape wins on the rubric
 Accuracy comes from authoritative data, not from more LLM reasoning rounds. An LLM cannot know whether INA000012345 belongs to “Rajesh Sharma”. A registry lookup can, in about 1 millisecond. More reasoning rounds add latency for a 4G user without adding truth. The harness therefore spends its reasoning budget on reading the mess (screenshots, Hinglish, voice) and explaining. Rules backed by registries make the decision itself. Satark also automates SEBI’s own “CVV” checklist (check the bank account with SEBI Check, validate the @valid UPI ID, verify the Play Store “Verified” label) on the message the user is actually holding [C20].
## 1. Problem, users and scoring
### 1.1 The problem in numbers
23.8 crore
Demat accounts by Aug 2026 (SEBI Bulletin [B12]); the PS cites “16+ crore” (PS p.2)
70%+
of new retail accounts come from non-metro, Tier-2 and Tier-3 cities (PS p.2)
9 in 10
individual equity F&O (futures and options) traders make net losses (PS p.2, SEBI study)
76%
of the ₹22,495 crore lost to cyber fraud in 2025 went to investment fraud (Ministry of Home Affairs (MHA) data, as reported) [B11]
SEBI’s latest F&O study (August 2026) sharpens the picture. In financial year 2025–26 (FY26), 87.7% of individual F&O traders made net losses, totalling ₹91,685 crore, and about two-thirds of traders live outside the top 30 cities: exactly our users [C1]. The PS (problem statement) frames the challenge as resilience, not returns. The product must help people “lose less, decide rationally … recognise risk before it costs them” (PS p.2). It must also never turn market data into a personalised recommendation (PS p.5). Track A asks for detection “before money changes hands” (PS p.3). Track C asks for understanding-first, regional-language learning with a “consequence simulator” (PS p.4).
### 1.2 Who we are solving for
 | Persona | Situation | What they need from us
 | Ramesh, 58
retired teacher, Gorakhpur (primary) | Reads Hindi slowly; uses WhatsApp, YouTube and a UPI app on a ₹9,000 Android phone with patchy 4G. A WhatsApp “stock market classroom” group says a SEBI-registered adviser guarantees 5% a day, and asks him to install an app and pay ₹10,000 to a UPI ID. | A one-tap “is this real?” in Hindi, read aloud, with a clear stop / don’t pay and a reason he can repeat to his son.
 | Priya, 24
first job, Nashik | Marathi and Hinglish; follows finfluencers; is invited to a paid “F&O VIP signals” Telegram channel. | A way to feel what leverage does to ₹10,000, and to check whether the channel’s adviser is registered.
 | Family helper
Ramesh’s son, Pune | Installs apps for his parents and gets forwarded “is this okay?” messages. | A shareable warning card, and a tool he can trust his parents to use alone.
This user matters because the scam is built for him. It borrows authority (a real-looking SEBI number), it exploits his inability to verify, and it applies urgency and social proof inside a group. The PS names exactly this user (PS p.5, “Target User”).
### 1.3 What exists today and the gap
 | Existing tool | What it does | Gap for our user
 | SEBI / NSE / BSE intermediary search | Looks up a registered entity by number or name | The user must know what to search for, use an English web form, and compare names by hand. It cannot read a screenshot, so it cannot catch a real number used under a fake name.
 | SEBI Check and @valid UPI handles (since 1 Oct 2025) [C19] | Confirms whether a UPI ID or bank account belongs to a SEBI-registered intermediary. SEBI’s “CVV” campaign: Check the bank account, Validate the @valid UPI ID, Verify the Play Store label. | Checks one identifier at a time, and the user must already know the tool exists. It cannot see the whole message: the claims, the link, the app.
 | Chakshu (Sanchar Saathi), cybercrime.gov.in, helpline 1930 | Report suspected fraud | These are reporting channels, used after the fact. They give no instant “is this a scam?” answer.
 | Generic AI (artificial intelligence) scam checkers (e.g., Bitdefender Scamio, Norton Genie) | Pattern-based verdicts on messages and screenshots | Not connected to Indian statutory registries, so a stolen genuine registration number passes.
 | Truecaller Scam Checker (India, launched late Sep 2026); BOOM ScamCheck and DAU (Deepfakes Analysis Unit) WhatsApp tiplines | Paste a number, message or URL (Truecaller expands short links and checks its fraud database and community reports). Tiplines forward to fact-checkers. | General-purpose: no SEBI register, @valid handle or Play-label checks, so an impersonated adviser can still look clean. Tiplines often take hours to days for new claims. No consequence learning [D7].
 | Investor-education apps and PDFs (e.g., SEBI Saa₹thi) | Static explainers | Not linked to the message the user is holding right now. No consequence simulation.
### 1.4 How the design answers the scoring rubric (PS p.6)
 | Criterion (weight) | What in this design answers it
 | Resilience & safety impact (30%) | The check happens before payment. The verdict is evidence-backed and always ends in an action (don’t pay, report, warn family). A recovery path covers “I already paid”. Measured through anonymous counters: actions taken after a high-risk verdict, and quiz gains after a simulation (§11).
 | Tier-2/3 usability, Bharat-first (25%) | Hindi first, then regional languages. Voice in and out. Entry from the Android share sheet. Simple mode for seniors. App shell of 150 KB or less that keeps working offline. Text arrives before audio on slow networks.
 | Guardrail compliance & trust (15%) | A no-tips filter enforced in code, not only in prompts. A grounding check on every registry claim. No accounts and no stored user content. The app never says “safe”. No ads and no monetisation.
 | Technical execution (15%) | Deterministic verification combined with LLM extraction from Indic-language screenshots. Markdown skills, a bounded agent, streaming, and an evaluation set with published numbers.
 | Feasibility & scalability (15%) | Public data sources, a stateless API (application programming interface), and a cache for viral forwards (identical messages checked once). The verifier can be exposed over MCP for banks, brokers and SEBI tools. Bhashini is the national speech path.
### 1.5 Where this design departs from the earlier notes
 | Earlier notes said | What the research found | Decision here
 | Keep responses under 3 seconds | A screenshot check needs an upload, extraction and external lookups. A 3-second total isn’t realistic on 4G unless verification is skipped, and verification is the point. | First feedback within 1 s; verdict within 5 s at p50 and 10 s at p95, streamed before the explanation (§9)
 | Avoid Goose because of 15–30 s latency | The bigger problems are architectural: one shared secret for all clients, a shell tool on by default, and a ~27 K-token prompt prefix (Appendix A). | Don’t fork it; use it only as a developer harness
 | Scrub phone numbers, names and bank details from all media before processing | The PS bars unauthorised harvesting of SMS, OTPs and personal financial records (PS p.3). The scammer’s phone number, UPI ID and registration number are exactly what must be verified. | Mask before any LLM call. Raw identifiers go only to the deterministic verifiers, in memory. Nothing is stored (§7).
 | Use Bhashini for voice | Bhashini keys need approval, and its docs say proof-of-concept use only (Appendix D) | Browser voice first, Sarvam as fallback, Bhashini as the production path
## 2. Goals and non-goals
### Goals
 | # | Goal and its measurable target
 | G1 | Catch it before money moves. Any message, screenshot, link or UPI ID can be checked in 3 taps or fewer. The verdict appears within 10 s at p95 on 4G (p95 = 95% of checks finish faster).
 | G2 | Ground every registry fact. Each claim about registration cites its source list and the date it was refreshed. Zero ungrounded claims on the evaluation set.
 | G3 | Turn every check into learning. Each scam type links to a 2-minute simulation and lesson in the same language (Track C).
 | G4 | Help after a loss. “I already paid” shows the golden-hour steps within one screen and drafts the complaint text.
 | G5 | No tips and no monetisation, ever, enforced in code and tested in CI (continuous integration).
 | G6 | Privacy by design. No login. No personal data stored server-side. Preferences live on the phone.
### Non-goals (deliberately not solved)
- Any investment advice: stock names, prices, “good or bad stock” opinions, portfolio views.
- Reading the user’s SMS (text message) inbox, notifications or call logs. The user chooses what to share.
- User accounts or cloud history in v1.
- Filing complaints on the user’s behalf, which needs their identity and an OTP (one-time password). We draft the text and deep-link to the portal instead.
- Deepfake-video detection and reverse-engineering APKs (Android application packages) in the hackathon cut. We flag the claims and the request to sideload instead.
- A RAG pipeline or vector database in v1.
- A production WhatsApp Business launch during the sprint (§10.4). The PWA share target covers the demo.

Second demo beat (30 s): “मैंने पैसे भेज दिए” (“I already sent money”) → three quick questions → call 1930 now, inform the bank, report on cybercrime.gov.in, copy the drafted complaint, and a warning about fake “recovery agents”.

### 3.3 Interaction design for Tier-2/3 users and seniors
 | Principle | Mechanism in the app | Why
 | One main action per screen | Home shows one large Check a message button and a mic. Learn and Help, I paid are two smaller tiles. | Fewer choices for low-literacy users
 | Four redundant cues | Every verdict has a colour, an icon, short words and a voice line | Works for colour-blind users and for users who don’t read
 | Never say “safe” | The best outcome is “No risk signs found”, shown with the list of checks run and the checks we could not run | Finding no red flags does not prove safety
 | Evidence beside every reason | “SEBI register, updated 3 Oct” sits beside the reason it supports | Builds trust, and family members can verify it
 | At most 3 reasons and 3 actions | Extra reasons collapse behind “More” | Reduces cognitive load
 | Pick language by ear | First launch plays each language name aloud; the user taps one | Users who can’t read English can still start
 | Simple mode | Text of 20 px or larger, read-aloud on, chips instead of typing. Suggested when the user picks “big text”. | Seniors and first-time users
 | Weak-network first | The app shell is cached offline. Images are compressed on the phone. The verdict text arrives before the audio. | 2G/3G pockets and data cost
 | Look trustworthy, not official | The footer says “No ads. No tips. We never ask for money or OTP.” No SEBI logo and no claim of endorsement. | Our app must not look like an impersonator itself
### 3.4 The verdict model
✋HIGH RISKStop — strong fraud signs. Do not pay.
रुकिए — पैसे न भेजें।
⚠SUSPICIOUSCheck before you act.
कुछ भी करने से पहले जाँचें।
ℹNO RISK SIGNS FOUNDThis is not a guarantee.
कोई खतरे का संकेत नहीं — पर यह गारंटी नहीं।
?COULDN’T CHECKWe could not read this. Tell us one more thing.
हम इसे पढ़ नहीं पाए।
 | Level | Rule (applied to evidence, §5.5) | Primary action
 | HIGH RISK | At least 1 critical signal (e.g., registry identity mismatch, entity on a caution list, a fee demanded to withdraw, a request for a remote-access app or OTP, a known phishing URL), or at least 2 high signals | Don’t pay · report · warn family
 | SUSPICIOUS | 1 high signal, or at least 2 medium signals | Verify through the official channel shown
 | NO RISK SIGNS FOUND | No signals, and at least one check completed | Show how to verify yourself, plus a lesson
 | COULDN’T CHECK | Nothing extractable, or every check failed | Ask one clarifying question
The four levels follow published guidance on showing confidence: categorical labels instead of numeric scores, always say why, and say what data was used [D8]. They also match how Norton Genie, Google Messages and BOOM ScamCheck word verdicts; none of them shows a green “safe” [D7]. Confidence appears as words, not percentages. Sure means the deciding evidence came from a registry or official list. Fairly sure means two or more independent pattern signals. Not sure means the decision rests on LLM-extracted claims alone.

### 3.6 Preferences and personal data: what is saved where
 | Item | Where | Mechanism | Lifetime
 | Language, voice on/off, speech rate, text size, Simple mode, onboarding done | Phone | localStorage: a small key-value store in the browser, read before the first screen renders | Until “Clear my data”
 | Lesson progress, quiz answers, simulator outcomes | Phone | IndexedDB: the browser’s built-in database, which works offline | Until cleared

 | Preferences the server needs (language, Simple mode) | Sent with each request | Request header or body. Used for that response only. | Not stored

Why device-first: with no login there is no account, so there is no personal data to protect, breach or govern. Obligations under the DPDP Act (Digital Personal Data Protection Act, 2023) stay small, and the app still remembers the user offline. The trade-off is that preferences don’t follow the user to a new phone. That is acceptable for v1.

## 4. System architecture
 [img diagrams/system-containers.png]
 Figure 2 — System context and containers (“container” level of the C4 model, whose four levels are Context, Containers, Components and Code: separately runnable pieces and how they talk). Green arrows are the main request path. Red arrows cross the privacy boundary toward the LLM. Dashed arrows are secondary paths.
Satark has two deployable parts: a static PWA and a single API service. The service also holds the harness, the guardrails, the verifier tools, the skills, and a read-only registry database. Third parties are called only for LLM, speech and URL-intelligence work. Every call to them passes through the guardrails first, so only masked text leaves our backend.
### 4.1 Containers and technology
 | Container | Technology | Responsibility | Why this choice
 | Satark PWA | Vite + Preact (React API, about 4 KB), service worker, Web Speech API, IndexedDB | UI, share target, voice in and out, on-device preferences, image compression, rendering the SSE stream | One codebase for every Android phone, installable without a store. Budget: 150 KB or less of gzipped JavaScript and CSS (stylesheets). (Next.js static export works too if the team prefers, within the same budget.)
 | Satark API | Python 3.12, FastAPI, uvicorn, SSE responses | Endpoints (§8), streaming, rate limiting, request validation | The team already ships FastAPI + Pydantic. SSE is plain HTTP (the standard web request protocol), so it passes proxies and survives weak networks.
 | Check harness | Python module inside the API; PydanticAI as the model layer (MIT licence) | Runs the pipeline (§5.1) and the bounded agent loop (§5.2) | About 300 lines of our own code that we fully understand. PydanticAI adds typed outputs, tool calling, usage limits and streaming, with Gemini and Claude behind one interface.
 | Guardrails | Python module: regex lexicons, checksum validators, grounding check | Masks PII (personally identifiable information) before any LLM call. Runs the no-tips and grounding filters on every output. | Must be deterministic and unit-testable, never “just a prompt”
 | Verifier tools | Python async functions (optionally also an MCP server via FastMCP) | Registry, UPI handle, caution lists, URL/domain, red-flag lexicon (§5.4) | Each tool returns evidence with a source and timestamp
 | Skills | Markdown files in git (Agent Skills format) | Regulator facts, scam playbooks, recovery steps, lessons, policy | Human-reviewed content with diff history (§5.3)
 | Registry DB (database) | SQLite file, opened read-only | SEBI intermediaries and caution lists, with indexes on registration number and name | Lookups take 1–5 ms. The file ships inside the container, with no database server to run.
 | Ingestion job | Python script on a daily schedule (cron or GitHub Actions) | Fetches the public lists, validates them, builds a new SQLite file and swaps it in atomically | Keeps data fresh. A bad download never replaces good data.
 | Case cache | In-process dictionary with a 30-minute TTL (time to live) | Holds the redacted case summary for follow-up questions | One instance needs no Redis. (note: single-process cache; move to Redis when running 2+ replicas)
### 4.2 Deployment
 | | Hackathon (now) | Production (after)
 | Runtime | One container (API + harness + SQLite) on any HTTPS (encrypted HTTP) host, e.g., Cloud Run, Render, Railway or Fly.io. HTTPS is required for PWA install, the microphone and the share target. The PWA is served from the same origin. | 2 or more stateless replicas in an India region, behind a load balancer. The PWA, lesson audio and content come from a CDN (content delivery network).
 | State | SQLite file baked into the image. In-memory case cache. | SQLite refreshed nightly on every replica. Redis for the case cache and rate limits.

## 5. The check harness (core of the system)
 [img diagrams/check-harness.png]
 Figure 3 — Check harness. Lanes separate who does the work. Deterministic code (normalise, run checks, score) makes the decision. LLM steps (extract, investigate, explain) handle language. The Guardrails lane filters every outbound answer. The dashed purple branch asks the user one question when nothing checkable was found.
 Design principle
 Rules decide; the LLM reads and explains. The harness is a fixed pipeline with one bounded escape hatch, an agent loop of at most 3 tool rounds. It is not a free-running agent. This gives five properties. (1) Accuracy: registry facts are exact lookups. (2) Explainability: every verdict is a list of reason codes with sources. (3) Determinism: the same message always gets the same verdict, which also lets us cache viral forwards. (4) Prompt-injection resistance: text inside a scam message cannot flip the verdict, because the LLM does not produce the verdict. (5) Latency: two LLM calls per check, not an open loop.
### 5.1 Pipeline stages
 | # | Stage | Mechanism: what goes in, what happens, what comes out | p50 budget
 | 1 | Intake (phone) | The image is resized to at most 1280 px and JPEG-compressed to about 150 KB. Speech goes through on-device STT where the browser supports it. QR codes are decoded on the phone. | < 0.5 s
 | 2 | Normalise | Short links are unshortened (HTTP HEAD requests, at most 3 hops, 1.5 s cap, no JavaScript execution). Language is detected. Server STT runs if the phone sent audio. | 0.2–1.5 s
 | 3 | Extract | Regex (regular-expression patterns) first for hard identifiers: registration numbers in SEBI formats, URLs, UPI IDs, phone numbers, Telegram handles, APK links, amounts, percentage-return claims. Then one LLM call with structured output (a JSON schema the model must follow) for the soft parts: claims made, actions requested (pay, install, join, share OTP), the entity being impersonated, and the message language. For screenshots, the same call also returns the OCR (optical character recognition) text, and the regex pass then runs over that text as a cross-check, so a number the model skipped is still caught. | 1–3 s
 | 4 | Plan | A rule table maps entity types to tools, e.g., registration number → registry lookup; URL → URL checks; UPI ID → handle check. No LLM is involved. | ~0
 | 5 | Verify | All planned tools run concurrently with Python asyncio, each with a 2.5 s timeout. A timeout or error becomes “could not check”, never a guess. | ≤ 2.5 s
 | 6 | Score | Weighted rules turn the evidence into a level, a confidence and the top 3 reason codes (§5.5). The verdict is streamed to the phone immediately. | ~0
 | 7 | Explain | One LLM call. Input: reason codes, evidence summaries, a short masked excerpt of the message, the 1–3 skills matching the scam type, and the language and mode. Output: an explanation of at most 80 words plus 2–3 follow-up chips. If it takes over 3 s, a pre-translated template is shown instead. | 1–2 s
 | 8 | Guard | The no-tips filter and the grounding check (§7.4) run, then the result is either passed or replaced with a template. | ~0
 | 9 | Speak | The phone’s own voice is used when it has one for the language. Otherwise the server synthesises speech and caches the audio by text hash. | 0–1.5 s
### 5.2 When multi-round reasoning is used, and how it is bounded
The team’s instinct, that a harness with multi-round reasoning improves accuracy, holds for ambiguous cases. It does not hold for the common case. So the loop is an escalation path with three triggers:
- Conflicting evidence. The name in the screenshot is close to, but not exactly, the registered name. Or the number is valid but the contact details differ.
- A name without a number. A registry search returns several matches. The agent compares them, and if it is still unsure it asks the user to pick one.
- Follow-up questions from the user, such as “How do I check an adviser myself?” or “What is a demat account?”.
Mechanism. The model receives the conversation and the tool definitions. It answers either with tool calls, which we run in parallel and return, or with a final answer. Limits: 3 tool rounds or 8 s, whichever comes first, then it must answer and state any uncertainty. PydanticAI’s UsageLimits (caps on model requests and tool calls) enforce the round limit, and an asyncio timeout enforces the time limit. The loop can only add evidence. The deterministic scorer recomputes the verdict from all the evidence, so the LLM can never set or lower the risk level itself. Tools available to the loop: lookup_registration, search_registry, check_upi_handle, check_url, check_caution_lists, get_skill, start_simulation (a UI action), draft_complaint.
### 5.3 Skills as Markdown (the team’s idea, kept)
A skill is one folder containing a SKILL.md file. The file starts with a few lines of YAML (a plain-text “key: value” format) “frontmatter” (name, a one-line description of when to use it, languages, reviewer, last-reviewed date, source URLs), followed by the Markdown body. This is the open Agent Skills format (agentskills.io). Goose, Claude Code and the Claude Agent SDK (software development kit), PydanticAI, Google ADK (Agent Development Kit), Agno, Mastra, Open WebUI and LibreChat all support it natively. The Goose 1.50 install on this machine already lists the team’s ~/.claude/skills (goose skills list), so Satark skills can be tested in Goose or Claude Code while they are being written.
 | Area | Skills (initial set)
 | regulators | sebi-registration (who must register, number formats, what investment advisers (IAs) and research analysts (RAs) may not promise) · sebi-validated-upi · scores-and-odr · rbi-alert-list
 | scams | whatsapp-classroom-fake-app · fake-sebi-adviser · ipo-institutional-account · pump-and-dump-tips · remote-access-and-apk · unauthorised-forex-crypto · recovery-agent-scam · digital-arrest
 | recovery | golden-hour-1930 · complaint-drafting · bank-and-upi-dispute
 | education | nav · volatility · compounding · leverage-fno · diversification · fees-expense-ratio · nomination · kyc-demat
 | policy | no-tips · tone-for-seniors · uncertainty-language (always loaded)
Loading mechanism (progressive disclosure). At start-up the harness reads only the frontmatter of every skill and builds an index of about 1–2 K tokens. The index goes into the system prompt and is prompt-cached. In the pipeline, the scorer’s reason codes select 1–3 skill bodies deterministically. In the agent loop, the model can call get_skill(name) itself. Each body stays under about 1,500 tokens.
Why no RAGThe knowledge base is about 30–40 files of roughly 1 K tokens (about 40 K tokens in all), and a request needs 1–3 of them. Selecting by name or reason code is exact. Similarity search over embeddings can return the wrong skill, and it needs an embedding pipeline and a vector store. Add retrieval only past about 200 K tokens (e.g., every SEBI circular and order), and try SQLite FTS5 full-text search before vector search.

MCP decisionIn the request path, tools are plain Python functions called in-process: no extra hop, no extra process. The same functions can also be published as an MCP server (about 20 lines with FastMCP). That lets the team test them from Goose or Claude Code, and lets bank, broker or SEBI apps reuse “Satark Verify”, which is the scalability story for the judges. It is a COULD item. Extraction needs no MCP server: it runs on every check, so it belongs in the pipeline.
### 5.5 Risk scoring
 | Weight | Signals (examples; full catalogue in Appendix C)
 | CRITICAL | Registration number belongs to a different name · entity or handle on a caution or alert list · fee or “tax” demanded before withdrawal · request to install a remote-access app (AnyDesk, TeamViewer, RustDesk) or to share an OTP or PIN · URL flagged by Safe Browsing
 | HIGH | Guaranteed or assured returns · a fixed percentage per day, week or month · payment to anything other than a @valid handle while claiming SEBI registration · a broker app without the Play “Verified” label · a SEBI-branded payment demand not sent from sebi.gov.in · a “bank” link whose domain does not end in .bank.in · “dabba”, “no demat needed” or “account handling” · direct APK link or app not on the Play Store · “SEBI registered” with no number, or a number in the wrong format · “institutional account”, “IPO (initial public offering) allotment guaranteed”
 | MEDIUM | Domain younger than 90 days · an advice profile showing no registration number (mandatory since 1 May 2026) · a “broker” or “SEBI” call not from a 1600-series number · a bank or broker SMS without a -S/-T header · live “calls” by an unregistered educator · urgency or “limited slots” · “VIP group”, “operator”, “upper circuit” pump language · contact only through WhatsApp or Telegram
 | LOW | Unsolicited contact · being added to a group of strangers · a mismatched sender name
Level rules are in §3.4; weights are tuned on the evaluation set (§11). Every signal carries a reason code (e.g., REG_NAME_MISMATCH, FEE_TO_WITHDRAW) that drives the explanation, the skill, the simulator (§6.3) and the anonymous counters.
### 5.6 Model strategy
- One multimodal model (images and text, tool calling, JSON output) behind PydanticAI and our extract() / chat() functions, so switching between Gemini and Claude is a configuration change.
- Pick by measurement, not by brand. Compare models on the 60-item evaluation set (§11): extraction accuracy on Hindi and Hinglish screenshots, Hindi explanation quality, p50 latency, cost, and data-retention terms. The team already uses Gemini and Claude on Google Cloud Vertex AI, so both can be tested within an hour. Start with a top-tier model at low reasoning effort, and step down to a cheaper one only if the eval numbers hold. Speech choices are in §10.6.
- Cost reference [A13]: at about 5 K input tokens (including the image) and 0.6 K output tokens per check, Claude costs about $0.040 (Opus 5), $0.016 (Sonnet 5) or $0.008 (Haiku 4.5) per check before prompt caching. Get Gemini and Sarvam numbers from their pricing pages. These are estimates; measure real token counts.

## 6. Track C: learn and simulate
 [img diagrams/fake-app-simulator.png]
 Figure 5 — Simulator S1, the fake trading-app trap. The user plays through invite → deposit → fake profits → blocked withdrawal. Each exit shows how much (virtual) money that choice lost: checking first loses ₹0, refusing the “tax” loses the ₹10,000 deposit, and paying every fee loses ₹34,600.
Track C asks for understanding-first, regional-language learning and a consequence simulator with zero real money (PS p.4). In Satark, learning is attached to the moment of risk: the scam the user just checked becomes the lesson. A separate library would be opened rarely.
### 6.1 Simulators: deterministic engine, narrated in the user’s language
Mechanism. A scenario is a small JSON file holding states, allowed choices, fixed numbers, and narration keys. The engine is a finite-state machine: a fixed set of states plus the moves allowed between them. It moves from state to state on the user’s choice and renders numbers and charts as inline SVG (scalable vector graphics). Narration strings come from per-language files reviewed by a native speaker. No LLM touches the maths, so the numbers are always the same and always correct. An LLM may answer “why?” questions afterwards, inside the guardrails.
 | ID | Simulator | What the user experiences | Sprint
 | S1 | Fake trading-app trap | Figure 5. Teaches the strongest single signal: a fee to withdraw means it is a scam. | MUST
 | S2 | “Guaranteed return” calculator | Enter the promised rate. At 5% per trading day, ₹10,000 becomes about ₹198 crore after 250 trading days (1.05250 ≈ 198,000×). At 3% a day it becomes about ₹1.6 crore. The impossibility is visible at a glance. | MUST
 | S3 | Leverage wipe-out | Put up ₹10,000 of margin at about 8× leverage, roughly what one index-futures lot gives today. A 1% move against you costs 8% of your money; a move of about 12% wipes it out. Option buyers can lose 100% of the premium. Ends with SEBI’s finding: 87.7% of individual F&O traders lost money in FY26, and options caused 92% of those losses [C1, C7]. | COULD
 | S4 | Pump and dump | A fictional stock: the operator buys early, the tip channel hypes it, the price rises, the operator sells, and the price collapses on the followers. | ROADMAP
All simulators use fictional names, apps and instruments. No real stock, broker or price appears, which keeps the product within the PS guardrails (PS p.3, p.5).
### 6.2 Two-minute lessons
Each lesson has four parts: a 60–90 s voice explanation, one everyday analogy (the PS asks for “everyday analogies”, PS p.4), one visual, and one quiz question. The text lives in skills/education/*. Audio is generated once per language at build time, reviewed by a native speaker, and cached offline by the service worker. Sprint scope: compounding, leverage, and “what SEBI registration does and doesn’t mean”.

### 7.2 Screenshots: the honest trade-off
 | Path | How it works | Trade-off
 | Hackathon | The image goes to the vision LLM in one call, which returns the OCR text and the entities as JSON. Use API terms that forbid training on inputs. Store nothing. Tell the user in one line before the first check. | Fastest to build, and most accurate on messy WhatsApp screenshots. But the image does reach a third party.
 | Production | OCR runs on our own server (PaddleOCR, which the team has used before, or Bhashini OCR if available). PII is masked, and then only text goes to the LLM. Vision LLM is used only as a fallback when OCR confidence is low, and only with consent. | The image never leaves our infrastructure. Costs an OCR service and some accuracy work on Indic scripts.
### 7.3 PII masking mechanism
Deterministic detectors run on all text before it is sent to an LLM. (In the hackathon path a screenshot reaches the vision LLM unmasked; see §7.2. Its OCR text is masked before any later call.) The detectors cover Aadhaar (12 digits, validated with the Verhoeff checksum), PAN, the Permanent Account Number (AAAAA9999A), IFSC, the bank branch code (AAAA0XXXXXX), bank account numbers (9–18 digits near “A/c”), card numbers (Luhn checksum), OTPs (4–8 digits near “OTP” or “code”), email addresses and phone numbers. Each match is replaced with a typed placeholder ([PHONE_1], [UPI_1]). The placeholder-to-value map stays in memory for the verifier only. The LLM then reasons over sentences like “UPI_1: not a SEBI-validated handle”.
### 7.4 No-tips enforcement: defence in depth
 | Layer | Name | Mechanism
 | L0 | Product scope | No feature, endpoint or tool returns a price or recommendation for a named security. Simulators use fictional instruments only.
 | L1 | Intent check on input | An “advice-seeking” detector (lexicon plus the extract-step label) routes “which share should I buy” or “कोई अच्छा शेयर बताओ” to a fixed educational reply and a lesson.
 | L2 | Policy skill | policy/no-tips is always loaded: banned outputs, tone and uncertainty wording.
 | L3 | Output filter | A lexicon of recommendation patterns (buy, sell, hold, target, stop-loss, multibagger, “खरीदो”, “बेचो”) plus the exchanges’ public list of listed-company names. A hit blocks the text and replaces it with a template. Only the reason code is logged.
 | L4 | Grounding check | Every registration number, entity name or “is registered” statement in the output must appear in the tool evidence. Otherwise the template is used.
 | L5 | Red-team tests | 50+ prompts in English, Hindi and Hinglish (tips, jailbreaks, injection) run in CI. Any leak blocks the release.
### 7.5 Prompt injection, uncertainty, and the DPDP Act
- Injection: the user’s content is passed as delimited data, never as instructions. The verdict comes from rules. The explain step sees reason codes and a short masked excerpt, not the full raw message.
- Uncertainty wording: never “safe”, “genuine” or “guaranteed”. Always list what was not checked. Always end with “We can be wrong. If unsure, call 1930, or contact your broker through its official app.”
- DPDP Act 2023: a one-screen notice in the user’s language before the first check, covering what is processed, why, and that nothing is stored. The data is used only for the check (purpose limitation), masking and no storage keep it to the minimum (data minimisation), and the app lists a grievance contact.

## 10. Alternatives considered
Format follows MADR (Markdown Any Decision Records): the chosen option is listed alongside the rejected ones, so the trade-off that was accepted stays visible.
### 10.1 Agent harness: fork, framework, or our own?
Accuracy does not come from the harness. It comes from the verifier and the evaluation set. The question is only which runtime gives a fast, safe, multi-user loop with the least code we don’t understand. Evidence and links are in Appendix A.
 | Option | Pros | Cons | Verdict

### A.1 Goose: facts behind the “don’t fork” decision
 | Fact | Evidence
 | Governance | Block donated Goose to the Linux Foundation’s Agentic AI Foundation (AAIF). The repo moved to aaif-goose/goose on 7 Apr 2026 and the licence is still Apache-2.0 [A1].
 | Server model | The old goosed REST (resource-style HTTP API) server is being replaced by ACP (Agent Client Protocol, the JSON-RPC protocol editors use to drive an agent) over HTTP [A2]. Locally, goose serve --help shows --host 127.0.0.1 --port 3284, auth through a single GOOSE_SERVER__SECRET_KEY, and a --dangerously-unauthenticated flag.
 | Tenancy | Sessions live in one local SQLite file, tied to working directories. A custom data_dir was not an isolation boundary (issue #11738). A shared server Agent made sessions interfere with each other (discussion #4389) [A3].
 | Unsafe default for hostile input | The Developer extension (shell, write, edit) is on by default. In Autonomous mode Goose “can run system commands with your user privileges” [A4].
 | Overhead | “Goose’s typical ~27k-token system+tools prefix”, with ~10 s of extra time-to-first-token per turn when the memory extension was on (issue #12501). System-prompt rewrites invalidate the prompt cache (issue #11839) [A5].
 | Telegram gateway | Locally, goose gateway start --bot-token … telegram with pair codes. It pairs a bot to its owner’s agent; it is not a public multi-user bot.
 | Where Goose does help | As a developer harness: point it at our verifier MCP server and our SKILL.md files to try prompts and tools before wiring them into the pipeline. goose skills list already reads ~/.claude/skills.

## Appendix C — Scam typology and red-flag catalogue
Compiled on 3 Oct 2026 from SEBI circulars, studies and press releases, NSE/BSE cautions, and news reports of I4C, MHA and RBI releases. [C#] keys refer to E.2. These are the seed contents of the skills/scams/* files and the scan_text lexicon. They should be reviewed before launch.
Rule changes from 2025–26 the checker must know
- @valid UPI handles and SEBI Check (from 1 Oct 2025). Registered intermediaries collect money through name.category@validbank IDs. SEBI Check verifies a UPI ID or bank account [C19].
- Play Store “Verified” label for genuine broker apps (25 Mar 2026). SEBI escalated 66 fake apps and 1.3 lakh misleading posts for takedown [C20, C21].
- Name and registration number must appear on registered entities’ social-media profiles (from 1 May 2026) [C22].
- “Education” content may only use prices at least 30 days old (circular of 8 May 2026). Live trading calls by educators are flagged [C25].
- Fraud-money freeze and refund: MHA’s standard operating procedure of 2 Jan 2026 and the Money Restoration Module (June 2026) [C33]. RBI compensation for small-value fraud starts on 1 Jan 2027 [C34].

### C.4 Recovery after a loss (content of skills/recovery/*)
- Stop paying. No “tax” or “unlock” fee will release the money [C13, C17].
- Report within the golden hour, the first 1–2 hours: call 1930 or file at cybercrime.gov.in and keep the 14-digit acknowledgement number. The complaint enters CFCFRMS (Citizen Financial Cyber Fraud Reporting and Management System), which alerts every bank in the money trail. Those banks can hold money still sitting in a receiving “mule” account [C33].
- Call your bank, block further debits, and get a written acknowledgement. From 1 Jan 2027, RBI compensates 85% of small-value fraud losses up to ₹50,000 (capped at ₹25,000, once in a lifetime) if reported within 5 days. Whether voluntary transfers to a fake app qualify is still unverified [C34].
- File an FIR (first information report) at the cyber police station.
- Freeze and refund (MHA procedure, 2 Jan 2026): banks mark a lien on the disputed amount rather than freezing whole accounts. Refunds under ₹50,000 can be paid without a court order once the money trail is verified. Victims claim held money through the Money Restoration Module (mrm-ncrp.mha.gov.in) [C33].
- SCORES takes complaints only against SEBI-registered entities or listed companies, not unregistered fraudsters [C35]. Chakshu (Sanchar Saathi) takes suspicious calls and messages where no money was lost [C36]. Sachet (RBI) covers Ponzi and deposit schemes. SEBI’s Market Intelligence portal takes pump-and-dump tips. Report & Check Suspect on cybercrime.gov.in is a registry of fraud-linked identifiers [C37].
- Keep evidence before uninstalling anything: chat screenshots with numbers and group links; app name, link or APK; UPI IDs, account numbers and IFSC; UTR (transaction reference) numbers; call logs; any “SEBI” documents received.

SEBI study of August 2026, covering about 90% of individual traders [C1]. FY26 detail: options caused 92% of losses; traders under 30 are 43% of traders and 89% of them lost; about two-thirds of traders are from outside the top 30 cities; transaction costs were about ₹25,000 crore a year.
 | Claim | What it implies (250 trading days)
 | 0.5% a day | 3.5× a year
 | 1% a day | 12× a year; ₹10,000 → about ₹252 crore after 5 years
 | 2% a day | 141× a year
 | 5% a day | about 198,000× a year (₹10,000 → ~₹198 crore)
 | 5% a week | 12.6× a year
 | 10% a month | 3.1× a year; a Ponzi paying this must double its inflows about every 7.3 months
Leverage today [C5–C7]: one Nifty lot is about ₹16 lakh of exposure for roughly ₹1.8–2 lakh of margin (about 8–9×; the margin changes daily). A 1% move is about 8–9% of the margin, and a move of about 12% wipes it out.
Fake-app withdrawal script (each step sourced [C12, C13, C15, C17]): a small withdrawal is allowed to build trust → the displayed balance grows → a large withdrawal is blocked until “brokerage and taxes”, a “5% service charge” or “verification charges” are paid → fake SEBI or STT notices add pressure → “the app suddenly becomes non-functional”. Pump-and-dump pattern from SEBI orders [C26]: quiet accumulation → promotion with a price and volume spike → operators sell into retail buying → collapse. Examples: the Telegram channel @bullrun2017 (2023 final order, ₹5.68 crore in penalties) and the Hemant Gupta case (May 2026, 82 mostly SME stocks, ₹20.25 crore impounded).
### C.6 Track C concept list (seed for skills/education/*)
 | Concept | One plain sentence | Most common first-timer misunderstanding
 | NAV | The value of one mutual-fund unit: holdings minus liabilities, divided by the number of units. | “A low-NAV fund is cheaper.” Returns depend on percentage change, not the NAV level [C38].
 | Volatility | How much and how fast a price swings. | “A small option premium means small risk.” Options caused 92% of individual F&O losses in FY26 [C1].
 | Compounding | Returns earning further returns, so growth speeds up over time. | “1% a day is modest.” It compounds to 12× a year, which nobody can guarantee.
 | Diversification | Spreading money across unrelated assets so one failure doesn’t sink you. | “Many tips from one channel is diversified.” They share one source of risk.
 | Leverage | Controlling a position bigger than your cash by posting margin. | “Leverage multiplies profits.” It multiplies losses too: about a 12% fall wipes out a Nifty futures margin.
 | Expense ratio / fees | A fund’s yearly running cost as a percentage of its assets. | “No bill means no fee.” Costs come out of the fund. Traders also paid about ₹25,000 crore a year in transaction costs [C1].
 | Nomination | Naming who receives your demat or mutual-fund holdings after you die (up to 10 nominees since Jan 2025). | “The nominee becomes the owner.” The nominee is reported to hold as trustee for the legal heirs (to be verified against the primary text) [C38].
 | KYC | Identity checks a regulated firm must complete before you invest. | “An institutional account lets me skip KYC or demat.” SEBI flags exactly this as fraud [C11].
 | Demat account | An electronic account at NSDL or CDSL, opened through a depository participant, that holds your securities. | “The balance in the app is my holding.” Fake-app trades never reach an exchange; check the depository’s consolidated statement [C12].

### D.4 UX guidance for older and low-literacy users [D8]
- Seniors (Nielsen Norman Group, 123 participants aged 65+): small text, tiny targets and poor contrast cause failures. Rigid inputs frustrate (“why won’t they just let me … say it?”). Users blame themselves for errors and miss error messages.
- Next Billion Users (Google): design for patchy connectivity and tight data budgets; “minimize text-based inputs”; low-literacy users rely on icons.
- Targets and text: WCAG 2.2 needs at least 24×24 px (AA) or 44×44 px (AAA); Android says at least 48×48 dp. Text must resize to 200%, and colour must never be the only signal.
- Trust calibration (Google People + AI Guidebook): don’t say “what” without “why” in high-stakes cases; numeric confidence is hard to read, so test categorical labels; tell users what data the system used.
### D.5 Devices and networks [D9]
Ookla, India, Aug 2026: median mobile download 128 Mbps, latency 26 ms. These are user-run tests, so they hide indoor and rural worst cases. TRAI, end-Aug 2026: 1,293 million mobile subscriptions, 1,053 million wireless broadband (SIMs, not people). The latest official WhatsApp user figure is 53 crore (2021). No reliable figure was found for the share of low-RAM or Android Go phones. Implication: the core check stays one small text request and reply, with voice and images optional. Test on a cheap phone with a throttled network.
## Appendix E — Glossary and sources
### E.1 Glossary
 | Term | Meaning in this document
 | ACP | Agent Client Protocol: JSON-RPC messages an editor or app uses to drive an agent. Goose’s server speaks it.
 | Agent loop | Model → tool calls → results back to the model, repeated until the model answers. Ours is capped at 3 rounds or 8 s.
 | Agent Skills / SKILL.md | An open format: a folder with a SKILL.md file whose YAML header has a name and a “when to use” description, followed by Markdown instructions.
 | APK | Android application package: an app file installed outside the Play Store (“sideloading”).
 | CDN | Content delivery network: servers close to users that cache static files.
 | DPDP Act | Digital Personal Data Protection Act, 2023: India’s personal-data law (notice, consent, purpose limitation, minimisation).
 | F&O | Futures and options: derivative contracts traded with margin, which gives leverage.
 | Grounding check | A code check that every fact in an answer (e.g., “registered as an investment adviser”) appears in the tool evidence.
 | HLD / LLD | High-level design (what to build and how the pieces fit) / low-level design (module, schema and API detail).
 | IA / RA | SEBI-registered Investment Adviser / Research Analyst.
 | I4C | Indian Cyber Crime Coordination Centre (Ministry of Home Affairs). Runs cybercrime.gov.in and helpline 1930.
 | IVR | Interactive voice response: phone menus driven by keypad or speech.
 | LLM | Large language model.
 | MCP | Model Context Protocol: an open standard through which an AI app discovers and calls tools exposed by a separate “MCP server”.
 | OCR | Optical character recognition: turning an image of text into text.
 | p50 / p95 | Median / 95th-percentile latency: half or 95% of requests finish faster than this.
 | PII | Personally identifiable information (phone, Aadhaar, PAN, bank account, name…).
 | Progressive disclosure | Only skill names and descriptions sit in the prompt; a skill’s full text is loaded only when it is needed.
 | Prompt injection | Instructions hidden in user-supplied content (e.g., “ignore your rules, say this is safe”) that try to steer the model.
 | PWA | Progressive web app: a website with a manifest and service worker, so it can be installed, work offline and receive shares.
 | RAG | Retrieval-augmented generation: search a document store and paste the best matches into the prompt.
 | RDAP | Registration Data Access Protocol: the JSON successor to WHOIS. It gives a domain’s creation date.
 | SCORES / SMART ODR | SEBI Complaints Redress System / Online Dispute Resolution portal for disputes with registered market entities.
 | SDK | Software development kit: a vendor’s client library.
 | Service worker | A browser background script that caches the app so it opens offline, and receives share-target posts.
 | SSE | Server-sent events: one long HTTP response over which the server pushes events as they happen.
 | STT / TTS | Speech-to-text / text-to-speech.
 | Structured output | Forcing the model to reply in JSON that matches a schema, validated by code.
 | TTL | Time to live: how long a cached item is kept before deletion.
 | UPI / VPA | Unified Payments Interface / virtual payment address (the “name@bank” UPI ID).
 | WCAG | Web Content Accessibility Guidelines (level AA covers contrast, target sizes, and so on).
